# 设置面板详解

本文是 [`README.md`](../README.md) 的补充：README 说明它是什么、怎么用；本文逐行说明**每一个设置**、它的默认值，以及这一行究竟影响哪些位置。

**每一个默认值都可以在代码里核对**，出处写在每一节的末尾。若干默认值是读者自己调好的数值，作为出厂值采用：新装的实例不需要调整任何一条，就已经是那个样子。

---

## 面板结构

工具栏右侧 **viewtune ⚙** 打开面板。分**三页**，键盘用**方向键**切换，`Home` / `End` 跳到第一页 / 最后一页：

| 页 | 内容 |
| --- | --- |
| **视效** | 动效、磨砂玻璃（开关 + 九个面 + 两个遮罩 + 对话页开关 + 整页纯色）、壁纸 |
| **功能** | 小功能（9 行）、正文显示（3 行）、流程展示设置（4 行） |
| **快捷键** | 本插件自己两个绑定的录制 |

一条排版约定：**加一个偏好就是加一行**，加一类就是加一页，工具栏不会因此变宽。**只有标签说不清的选项才带说明**，那句说明挂在该行的 `title` 上（浏览器原生提示框），平时不占版面；被系统覆盖、正在录制、组合被拒这类**状态**直接写在行里。

## 视效

### 动效

控制本插件的动画与过渡（卡片的展开与收起、流程的展开、正文的显现动画）。

- 被系统的「减少动态效果」覆盖时，行里会写明这一点；
- **它不影响"是否跟随"**：思考卡的自动跟随与暂停跟随在动效关闭时照常工作，只是改为直接跳到最新位置，而不是滑动过去。把跟随开关交给一个外观开关，会让关掉动效的读者失去一项阅读功能。

*出处：`store.ts`（`motion: true`）、`ReasoningCard.tsx`（跟随的判据不含动效）。*

### 磨砂玻璃

总开关。打开后，工具栏、卡片、工具框与代码块不再使用不透明的底色，而是让壁纸与宿主底色透出来。

**每一个面有两条档**：

- **透明度**：这个面透出多少壁纸。`0%` 表示这个面什么都不绘制，`100%` 表示关闭皮肤时那块不透明底色；
- **模糊值**：透出来的是照片本身还是一层模糊。`0px` 表示只有透明、没有模糊。模糊值调到最低时，插件会**删除该属性**而不是写入 `0px` —— `backdrop-filter: blur(0px)` 不等于没有模糊，它会创建层叠上下文并把绘制交给合成器，代价是白付的。

| 面 | 管哪些位置 | 透明度 | 模糊值 |
| --- | --- | --- | --- |
| 工具栏 | 顶部那条工具栏、浮在正文上的「回到最新」胶囊，以及对话页宿主自己的「回到底部」按钮 | 10% | 0px |
| 用户气泡 | 读者自己那条消息的底色 | 30% | 3px |
| 卡片与面板 | 思考卡、工具框、系统提示词、备忘框等面板 | 25% | 8px |
| 代码块 | 围栏代码块的底色 | 35% | 25px |
| 差异面板 | 差异面板与增删行的底色（含行号槽）、文件标签、工具结果里的行内差异，以及对话页那张「已编辑 x 个文件」卡（含卡头与悬停详情）、对话页同一处每文件一张的产物卡（含悬停色） | 30% | 25px |
| 滚动条槽位 | 最右侧那条滚动条的轨道 | 20% | —（槽位是滚动条伪元素，模糊对它无效，因此没有这一条档） |
| 产物栏 | 一轮末尾那栏产物文件 | 35% | 5px |
| 用量与步骤胶囊 | 「用量 … tok / … 个步骤」两枚计数胶囊 | 30% | 2px |
| 输入框 | 宿主输入框的底色（阅读页与对话页都生效） | 35% | 10px |

**两个遮罩**（侧栏遮罩 / 顶栏遮罩）是同样的两条档，管的是壁纸之上那层压暗：出厂为**侧栏 25% + 15px**、**顶栏 25% + 5px**（两个面的模糊是两个独立的数值）。同样在 `0px` 时删除属性，避免这两个元素重新获得合成层。

**分组按"是什么"而不是"在哪里"**：差异纸无论画在差异面板里还是工具「结果」页里，都归「差异面板」。**只有本来就有底色的面才有旋钮** —— 工具状态与行数计数在基础样式里没有静止底色，所以不接任何旋钮。

**对话页**：同一个皮肤可以延伸到对话页（独立开关「为对话页启用」）；那里还有「整页纯色」这个独立选项（主题底色 + 输入框上方一条淡出），与皮肤互不依赖。

*出处：`glass.ts`（九个面与两个遮罩的初始值）、`wallpaper-scope.ts`（遮罩）、`conversation-glass.ts` / `conversation-solid.ts` / `composer-glass.ts`（对话页）。*

### 壁纸

自带一张默认壁纸 `assets/sample-gradient.png`：第一次启动时由宿主放进读者的壁纸文件夹，新装上去打开就是这个样子，不必先自己找图。

- **暗度**：0–100，出厂 **50**；
- **作用范围**：整窗 / 仅正文区域等（`wallpaper-scope.ts`）；
- 列表来自宿主的壁纸文件夹（`/better-display/wallpapers`）。

*出处：`wallpaper.ts`（`DEFAULT_WALLPAPER`、`WALLPAPER_DIM_INITIAL = 50`）、`wallpaper-scope.ts`。*

## 功能

### 小功能（9 行）

| 行 | 作用 | 默认 |
| --- | --- | --- |
| 竖条滚轮缓动 | 鼠标位于滚动条形状的区域（例如横向列表）时，滚轮的处理方式 | 开 |
| 产物用侧边栏打开 | 点击产物时，交给宿主的右侧栏打开，而不是外部打开 | 关（外部打开） |
| 产物展示方式 | 一轮末尾的产物画成什么：**简略** / **平衡** / **卡片** | 平衡 |
| 新会话默认视图 | 新开的会话先落到**阅读页**还是**对话页** | 阅读页 |
| 记录 git 提交 | 一轮末尾多出「提交」那一栏气泡（消息作标签、短哈希进悬停、点击复制） | 关 |
| 差异在侧边栏审查 | 「共 x 项编辑」交给**宿主自己的审查面板**，而不是阅读页自己的差异面板 | 关（用阅读页自己的面板） |
| 自动收起更早流程 | 较早的轮次只显示正文，流程收起 | 开 |
| 自动折叠更早的轮次 | 只保留最近若干轮的完整内容，更早的轮次不渲染；`0` 表示全部保留 | `0` |
| 收起按钮的行为 | 工具栏那个按钮与快捷键**做什么**：收起上一轮 / 收起全部 / 默认 | 默认（两者都在） |

*出处：`store.ts`（`init`）、`deliverables.ts`（三档展示与打开方式）、`entry-policy.ts`（新会话默认视图）、`turn-fold.ts`（折叠窗口）、`collapse-mode.ts`（收起行为）。*

### 正文显示（3 行）

| 行 | 作用 | 默认 |
| --- | --- | --- |
| 逐词显现 | 新到的正文按词显示，而不是整段出现 | 开 |
| 逐词显现的模糊 | 显现过程中带模糊。**逐帧重绘的代价由读者自己权衡**，因此默认关闭 | 关 |
| 正文更新节奏 | 跟随显示刷新率，或固定 60 次/秒 | 跟随显示 |

逐词显现关闭时，后两行的关联项会置灰（它们只在逐词显现打开时有意义）。

*出处：`store.ts`（`revealWords: true`、`revealBlur: false`、`textCadence: 'steady'`）、`text-cadence.ts`。*

### 流程展示设置（4 行）

| 行 | 作用 | 默认 |
| --- | --- | --- |
| 跟随到最新 | 页面跟随新内容的方式（直接贴到最新位置，或按节奏跟随） | 直接贴到最新 |
| 思考卡的自动跟随方式 | 思考卡的自动滚动：跟随最新 / 手动 | 跟随最新 |
| 自动滚动的速度 | 思考卡与正文跟随的节奏 | 3 |
| 焦点思考展开 | 正在被写入的思考卡展开显示内容；在卡片内部滚动会保持它展开 | 开 |

「自动滚动的速度」只在「思考卡的自动跟随方式」为**跟随最新**时有效，否则置灰。

*出处：`store.ts`（`followMode: 'snap'`、`reasoningFollow: 'latest'`、`reasoningRate: 3`）、`reasoning-follow.ts`、`focus-expand.ts`。*

## 快捷键

本插件有两个可以绑定的动作：

| 动作 | 默认 |
| --- | --- |
| 收起当前轮 | `Alt+C` |
| 收起全部 | `Alt+Shift+C` |

录制方式：点击键帽开始录制，`Esc` 取消，清除后即不带快捷键。两条规则保证它可以安全地占用文档级键盘事件：

- **必须有修饰键**：单个字母这类组合会被拒绝，否则读者在输入时会误触；
- **已被浏览器占用的组合会被拒绝**。

「收起按钮的行为」是**行为**而不是绑定，所以它在**功能**页的「小功能」组里（见上表最后一行）。

*出处：`shortcuts.ts`（`DEFAULT_SHORTCUTS`）、`store.ts`（`shortcuts` 只记录改动过的键）。*

## 设置存放在哪

- 保存在**宿主**的插件记录里（`/better-display/settings`），由宿主负责落盘（写临时文件再改名）；
- **只保存读者改过的键**：没有改过的项不写入记录，缺失的键使用出厂值；
- **读取方式是防御式的**：早期版本写下的记录缺少后来新增的键时，每一项都按"缺失即出厂值"处理，因此升级不会丢掉读者的选择；
- **写入方式**：每次改动写入整份记录。代价与它为什么可以接受，写在 README 的「已知限制」里。

*出处：`settings-sync.ts`、`store.ts`（hydrate 与默认值的读取方式）、`dsh-viewtune.ts`（服务端读写）。*
